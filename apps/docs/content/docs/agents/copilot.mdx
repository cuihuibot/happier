Happier can run **GitHub Copilot CLI** through the local `copilot` binary on your machine.

<Callout type="info">
  Copilot is an **experimental** integration. It works and people use it
  daily, but its surface is younger than Claude, Codex or OpenCode and is
  more likely to change. What it supports today is in
  [Agent capabilities](/agents/capabilities).
</Callout>

## Requirements

- Copilot CLI installed locally
- binary available on `PATH` (or configured through Happier’s CLI path settings)

## Install Copilot

Happier can install it for you:

```bash
happier install provider copilot
copilot --version
```

Or install manually:

```bash
npm install -g @github/copilot
copilot --version
```

## Choose authentication for a new session

Copilot can use either a connected GitHub token profile or the selected machine's native authentication.

<Callout type="info">
  Connected GitHub profiles for Copilot are currently available only in
  development builds. This support has not been included in a published
  release yet.
</Callout>

To use a connected profile, choose it in the new-session auth picker before starting Copilot. Happier supplies the selected token to the new Copilot process as `COPILOT_GITHUB_TOKEN`.

The token is projected only when the process starts. Its value is not stored in session metadata. If the selected GitHub credential is not token-based, Happier rejects it instead of falling back to another credential.

Copilot CLI 1.0.86 checks token sources in this order:

1. `COPILOT_GITHUB_TOKEN`
2. `GH_TOKEN`
3. `GITHUB_TOKEN`
4. Copilot's stored login credentials

This means an explicitly selected connected profile takes precedence over ambient environment variables and stored Copilot login credentials for that process.

If you leave GitHub on **native** authentication, Happier does not project a connected token. Copilot keeps using the machine's existing environment variables, local `gh auth token`, or Copilot login behavior.

GitHub OAuth profiles are not supported for Copilot in this build.

## Manage native authentication

Happier shows Copilot’s machine-local auth state in:

- **Settings → AI & Agents → AI backends → Copilot**

From there you can:

- check whether Copilot is authenticated on the selected machine
- open the native `copilot login` flow directly inside Happier
- refresh the auth status with **Check now**

Happier currently detects Copilot auth from:

- `COPILOT_GITHUB_TOKEN`
- `GH_TOKEN`
- `GITHUB_TOKEN`
- the local GitHub CLI auth state when available

For the shared user guide, see [Provider authentication](/agents/provider-authentication).

## Notes

- Native Copilot auth is machine-local. If you log in on one machine, another machine still needs its own local login or a connected GitHub token profile selected for the new session.
- Happier can detect token-based native auth and show it as an environment-backed method.

## Troubleshooting

If Copilot is not detected:

1. Verify `copilot --version` works.
2. Restart Happier.
3. Re-open the provider settings page and use **Check now**.
