Happier can run **GitHub Copilot CLI** through the local `copilot` binary on your machine.

<Callout type="info">
  Copilot is an **experimental** integration. It works and people use it
  daily, but its surface is younger than Claude, Codex or OpenCode and is
  more likely to change. What it supports today is in
  [Agent capabilities](/agents/capabilities).
</Callout>

## Requirements

- Copilot CLI installed locally
- binary available on `PATH` (or configured through Happier’s CLI path settings)

## Install Copilot

Happier can install it for you:

```bash
happier install provider copilot
copilot --version
```

Or install manually:

```bash
npm install -g @github/copilot
copilot --version
```

## Local authentication in Happier

Happier shows Copilot’s machine-local auth state in:

- **Settings → AI & Agents → AI backends → Copilot**

From there you can:

- check whether Copilot is authenticated on the selected machine
- open the native `copilot login` flow directly inside Happier
- refresh the auth status with **Check now**

Happier currently detects Copilot auth from:

- `COPILOT_GITHUB_TOKEN`
- `GH_TOKEN`
- `GITHUB_TOKEN`
- the local GitHub CLI auth state when available

For the shared user guide, see [Provider authentication](/agents/provider-authentication).

## Notes

- Copilot auth in Happier is machine-local. If you log in on one machine, another machine still needs its own local login.
- If you prefer token-based auth, Happier can detect that and show it as an environment-backed method.

## Permission waits in the approved CLI candidate

<Callout type="warning">
  This behavior belongs to approved product candidate
  `4a4574a84f387933c58992eb4b66b909e6b97a8c`. It is not installed. The current
  installed stack remains `0.2.12-cuihui-acp-stall-v1`.
</Callout>

When an ACP permission prompt is visible and can still be answered, Happier
keeps the turn open without imposing a deadline on the person deciding. If a
prompt that was actionable stops being answerable, Happier confirms the loss
twice before ending the stuck turn with a visible sanitized failure. With the
default 5-second recheck interval, that normally takes about 10 seconds, subject
to timer scheduling.

The check applies to each current-turn permission independently. An actionable
sibling keeps the turn alive, while a sibling that has not been published yet
receives normal publication grace without hiding a different request whose loss
has already been confirmed. Prompts from earlier turns cannot keep a later turn
alive.

This does not change approval or denial behavior and does not automatically
replay the prompt, because a tool may already have produced effects. Explicit
caller timeouts and explicit timeout opt-outs are unchanged.

Operators can change the recheck interval by setting
`HAPPIER_ACP_PERMISSION_RECHECK_MS` to a positive integer number of
milliseconds. The default is `5000`. This is separate from the existing
600-second implicit response-completion stall budget.

## Troubleshooting

If Copilot is not detected:

1. Verify `copilot --version` works.
2. Restart Happier.
3. Re-open the provider settings page and use **Check now**.
